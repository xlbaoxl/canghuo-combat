# 战前作战配置与自动演算

> 记录日期：2026-10-13。依据本会话最近三轮可见讨论整理，不是逐字聊天稿。
> 状态：**作者已明确新的操作方向；调度、冷却与阵位细则待定；尚未实现。**
> 现有 3.0.1 源码及线上 3.0.1-web.2 保持原状。本文件不能作为新模式已经可玩的证据。

## 1. 作者最新明确的方向

战前完成角色、技能装配及技能用法配置；战斗开始后由系统统一演算双方出手与选目标，玩家主要观看战斗表现，不再承担逐人逐技能的临场输入。

| 决策内容 | 新方向中的归属 |
|---|---|
| 带哪些成员、装配哪些功法和法宝 | 战前由玩家配置 |
| 每个角色内部的出招配置 | 沿用前轮战前配置思路；具体执行粒度仍待定 |
| 双方成员出手先后 | 系统统一演算，不再由玩家安排己方整队先打完 |
| 每门技能攻击谁 | 玩家战前为该技能设置选目标意图，执行时由系统求出具体目标 |
| 战中逐轮选人、排列己方顺序、逐人点目标 | 不再作为常规必需操作；按作者“看动画就行”的最新边界理解 |

作者明确以《圣兽之王》的战前作战配置与自动交战作为更接近的方向。借鉴范围是操作分工，不自动采用该作整套资源、行动次数、阵型或战场移动规则。

## 2. 讨论是怎样走到这里的

第一步：作者担心九人队伍逐个选择技能的操作负担，提出战前为每人配置一套出招；战中只选择本轮哪些人出手及顺序。例子是 A/B/C/D 全员出手、下一轮只 A/B、再下一轮只 C/D。

第二步：作者进一步提出九对九还需逐人点受击目标，要求重新思考选目标和九格阵型的含义。助手提出过全队统一进攻重点、前后掩护、三个小队等候选；这些没有获得作者采用。

第三步：作者明确把双方出手先后交给系统，避免一方全员先出手；战斗意图下放到每一门技能，例如同一个灵气刃可以选“血量最低”或“修为最低”，战中无需操作、观看动画。

**据此撤回“玩家每轮排己方顺序”和“全队共享手动目标”作为新方案的建议前提。**不能一边说自动战斗，一边要求玩家每轮重新选九个人或指定九次目标。也不能把助手此前提出的强制三人分组、全队集火或前排保护自动升级为共识。

## 3. 前轮技能 CD 与整套出招的设想仍需保留

作者的 A 角色示例：法宝普攻、小技能 CD1、中技能 CD2、大技能 CD3，按配置顺序执行当下可用的技能，而不是只挑其中一个。

| 动作 | 第一轮全就绪时 | 紧接下一轮再次出手时 |
|---|---|---|
| 法宝普攻 | 执行 | 可执行 |
| 小技能 CD1 | 执行 | 恢复，可执行 |
| 中技能 CD2 | 执行 | 尚差一轮，跳过 |
| 大技能 CD3 | 执行 | 尚差两轮，跳过 |

以上只记录作者给出的连续出手例子：保留技能各自 CD，部分技能未好不阻止角色使用其他已就绪技能。**不能由于参考《圣兽之王》，擅自改为一动只选一招、引入 AP/PP，或取消 CD。**

例子尚未确定冷却使用公共轮、个人行动还是其他时钟；未出手/无法行动时如何恢复也未确定。“一次出手按序执行多门技能”与“每门技能之间允许其他角色行动”能否兼容，需要下一步明确。不能把逐技能执行、动画帧数或动画长短当作已经采用的冷却时钟。

## 4. 每门技能的意图，不是每个人或全队一个目标

同一个灵气刃可以根据战前配置形成不同用法：A 的灵气刃优先处理血量最低的合法敌人，B 的灵气刃优先处理修为最低的合法敌人。即便角色相同，不同技能也不必共享同一个主目标。

作者已明确的是“为技能选择目标意图”。以下为助手的细化建议，尚不是已定实现：

- 将“技能能对谁使用”与“在合法对象中优先选谁”分开。目标意图不额外赋予穿透保护、跨阵位、攻击友方等能力。
- 选目标策略归属该角色的该技能配置，不因为改变策略就复制一门新功法、重置 CD/熟练度或增加功能句 N；实际技能效果与施放策略分开记录。
- 每次真正施放前按当时战场重新选目标。不能开场把九个人的所有目标锁死，也不在目标倒下时弹窗要求玩家接管。
- 一门已经开始结算的技能，其多段/同组目标锁定仍需明确契约，不能把“下一门技能重新选目标”误写成“每一段伤害都自动换人”。

最低血量是剩余气血绝对值还是百分比，修为最低按什么现有数据比较，排序并列如何确定、没有合法目标时如何处理，均待定。尤其不能把“修为最低”擅自等同于“防御最低”“气血最低”或笼统战力最低。

目标优先级与施放条件也要区分：“优先血量最低”不等于“只打低于某血线的敌人”。治疗阈值、保留灵气、目标无某 Buff 等条件可作为之后的候选，不在本轮建立任意脚本编程系统。

## 5. 系统调度仍有一个关键未决问题

**谁先行动，与一次行动占用多少连续执行机会，是两个问题。**

| 候选执行方式 | 含义 | 主要代价 |
|---|---|---|
| 角色整套执行后再换下一角色 | 保留前轮完整连招的直观语义，双方角色由系统混合排序 | 最先行动者仍可能连续打出普攻加多门技能，先手爆发必须验证 |
| 在技能之间安排双方动作 | 角色内部配置仍给出先后，但下一门需等系统调度，敌人可能在其间行动 | 更易形成穿插，但改变“整套连续兑现”的体验及行动/冷却语义，需作者选择 |

本轮只确认顺序不由玩家临场指定，没有选择上述任一项。系统排序不等于随机排序，也不等于强制双方一人一替；纯速度排序本身仍可能使一方多人连续领先，不能宣称已经解决所有先手压制。

具体速度公式、是否每轮每人一次、初始技能是否全就绪、准备/恢复时间、反应插入、死亡/控制的取消边界都未定。可用小规模镜像例子检验先手伤害与回应机会，不先堆完整九对九内容或用删减角色技能掩盖问题。

## 6. 九个位置的含义仍未定

新操作方向下，九名成员不需要对应九份战中指令。格子可用于战前编队，也可能形成前后保护、行列范围、邻接支持等关系；作者尚未确定采用哪一种。

阵位解决“哪些对象可被作用、谁与谁形成关系”，技能意图解决“在允许的对象中优先选谁”，两者不能混为一条任意自动选人规则。也不能仅因要降操作，就强制三个三人小队、移动走格子或全队锁一个敌人。

## 7. 观战与反馈的候选要求

玩家不点招以后，需要能看见配置如何生效：本次技能因哪条意图选择了谁，哪些技能因 CD/费用/条件被跳过，为什么下一位先行动。建议用简短提示、行动顺序预览和可展开战斗记录解释，而非每个决策弹窗。

暂停、加速、重播属于观看工具的候选，不恢复临场技能决策。配置模板、复制策略可降低九人多技能的战前重复设置；它们未在本轮制作。

理想验证过程是：配置 → 观察执行与结果 → 修改配置 → 再战。不能把纯动画顺畅或测试数量当作阵容平衡、策略深度或玩家认可的证据。

## 8. 与现有 3.0.1 的关系及实施边界

[总纲](战斗设计总纲.md)与[讨论沿革](讨论共识与演变.md)中此前“战中手动应变”“普通一次主动作、战机多入口”的记录，仍解释现有 3.0.1 的来源与实现；不能拿旧操作目标否决作者本次新方向，也不能用这次方向讨论冒充它们已被代码替换。

新模式是否保留 A/Z/W/R、战机如何表现、CD=N 是否继续绑定结构，以及阵法布阵/持阵的时钟映射，必须在迁移设计中单独列明。本轮不偷改旧规则，也不要求为了兼容旧按钮而把逐人操作塞回新模式。

**不再由玩家点击《催》，不等于删除《催》的独立能力。**若进入新模式，应明确它如何由配置调度；法宝事件自动效果和《催》独立效果的来源、费用、CD 与触发次数仍须分开。既有支付/伤害区分、结算记录等可复用，不直接宣称已经完成多角色自动调度。

本轮交付仅为新方向与讨论演变记录、首页导航，不修改游戏源码/数值/资源/工作流，不重新发布网站。细则与小规模验证确定后再另开实现任务。[3.0.1 源码入口](3.0.1源码入口.md)继续保留作对照基线。
