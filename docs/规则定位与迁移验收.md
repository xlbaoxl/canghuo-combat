## 1. 一张表找到规则放在哪里

下表的行号只适用于固定源 `modules/training-camp/project/scripts/battle.gd`，不是后续重构文件的永久行号。可用函数名再次定位。

| 职责 | 基线入口/行号 | 本次核对的实现状态 | 下一步责任边界 |
|---|---|---|---|
| 初始化与入场 | `start` L19 | 先建立所有单位，再收集法宝入场响应 | 不把入场效果藏进UI构造或动画回调 |
| 时钟与调度 | `advance` L153、`public_tick` L256 | A/Z资格、公共刻、队列与就绪单位排序均在共同执行器 | 保持实际排序；迁移不能变为敌我固定交替 |

## 2. 十一项基础Buff的迁移检查单

下列不是新的数值方案。每项先保持3.0.1算法和时钟，再把行为从主流程移到对应接口。接口名是内核方案中的职责名，不代表现在已有同名类。

| 规则 | 当前介入点 | 目标接口 | 必须保留的反例 |
|---|---|---|---|
| 护体 | 伤害组；施加时Hmax上限 | 防护处理与状态上限 | 不吸收效果伤害或气血支付；同池总量仍有上限 |
| 锋锐 | 独立直接攻击组 | 攻击修正＋一次消耗计划 | 一个攻击打多人不按人数消耗；自动法宝不借用；主动《催》的本人攻击仍适用 |
| 神速 | 公共刻A增长 | 公共刻计划修正 | 不改S排序或Z自然增长；不能额外创造窗口 |
| 凝神 | 主动施法费用报价 | COST修正 | 最低费用0；不改CD；重复预览不消耗 |
| 鲸吞 | 公共刻回气 | 公共刻计划修正 | 实际回复受M限制，溢出可对账 |
| 回春 | 公共刻共同净提交 | 周期请求＋层数变化计划 | 与侵袭同批；不能独立先加H再让侵袭判死 |
| 侵袭 | 同上 | 同上 | 当前层贡献后减半；新层不追溯参与已提交的刻 |
| 蚀骨 | NORMAL_PRE | 普通周期任务 | 战机前不额外结算；窗口前死亡不推进W/R |
| 撕裂 | 费用报价＋普通回合结束 | COST修正＋生命周期 | 主动布置/施法收费与普通结束衰减分开；自动效果不支付 |
| 逆气 | 主动施法费用报价 | COST修正 | 不改技能回转或成品承载；《催》正常适用 |
| 滞气 | 公共刻回气 | 公共刻计划修正 | 保留基线最低1；不关闭合法装配法宝 |

无常印记另列为无自动收益的状态存取，不把它因迁移表格自动升级为第十二个基础Buff。法宝、阵势、灵宠是来源/载体身份，不是新的“万能Buff类”。

## 3. 分清三个状态，避免做出空接口

**有阶段名字：**程序能表示现在处于哪个阶段。

**有事实记录：**程序把已提交的支付、攻击或状态变化记录下来。

**有可接入契约：**模块能在明确节点收到限定输入，并返回受限结果，且该结果真的经过统一提交。

3.0.1已经具备前两者的较多内容，但第三者尚未完整实现。`record("SPELL_FINISHED", ...)`不意味着任意状态已经能订阅技能结束；`BUFFS`中的一段说明也不等于行为由数据驱动。验收必须实际注册一项测试效果并检查调用、边界和移除，不以函数/枚举存在作为完成证据。

## 4. 一次施法的追踪单

本节将既有讨论转成调试需要记录的字段，不扩展命中、暴击、反伤等尚未采用玩法。

| 检查点 | 需要看到的输入/结果 | 出错时优先查哪里 |
|---|---|---|
| 预览 | 版本、人物与目标快照、效量、费用 | 纯解析器是否与真实执行一致 |
| 开始核验 | 主动作、入口、CD、整门条件、支付能力 | Eligibility；失效命令是否未改状态 |
| 提交 | 支付者、资源变化、W、恢复窗口、动作/施法ID | Action事务；是否重复付费或推进窗口 |
| 单句准备 | 句ID、操作、读取时点、目标、前句引用 | 表达式与结构校验；0与未执行是否区分 |
| 攻击计算 | 基础量、每项修正、吸收量、实际损失、过量 | 伤害处理器；是否把支付误分类为伤害 |
| 组提交 | 共同快照、所有目标结果、状态消耗 | 原子组；是否被目标遍历顺序影响 |
| 组后响应 | 父事件、实例、资格依据、优先次序、取消原因 | Reaction队列；是否追溯修改了旧伤害 |
| 施法收尾 | completed/interrupted/terminal、各句结果 | 不因后句失败退回已经完成的前句 |
| 交还控制 | 当前窗口类别、合法入口与调度理由 | 普通/战机流程；动画不能取得调度权限 |

示例追踪链：`护体增加30 ← 阵势实例响应D17 ← D17实际损失60 ← 伤害请求100，原护体吸收40`。这是解释结构的例子，龟甲阵的返盾基数仍按专题里的未决状态管理。

## 5. 每个新词条的最小交付

普通扩展进入内容库前，应有以下一组资料，不要求每条都新建文件：

1. 定义：稳定ID、采用身份、所属接口、读取/写入权限、参数、取整、次数作用域和生命周期。
2. 来源：人物主动、自动法宝、主动《催》、状态或阵势；所有者、执行者、支付者分别说明。
3. 正向样例：一个能生效的明确场景及预期结果。
4. 反向样例：一个不能触发/不能支付/不能重复的场景及理由。
5. 组合样例：与至少一种相邻规则同时存在时的顺序或数值检查。
6. 清理样例：移除、到期、来源失效、读档或AI副本中不留下重复监听和任务。

“效果很多”不是“接口种类很多”。纯参数变体用配置；新增局部机制用受限处理器；需要中断、复活、改时钟等权限时，必须明列协议变更，不能用高优先级回调越权。

## 6. 阵法接入的独立检查

阵法需要可取消的延迟任务、阵势实例和主动入口状态，不修改普通CD到期的含义。

- 布阵已结束，只留下到期任务；不是让一次施法挂起数个回合。
- 到期激活不再扣一次开始费用，不消费一次新主动作。
- 持阵是即时技能，不复制布阵延迟。
- 受伤返盾产生新的护体请求，不回写旧伤害。
- 撤阵同时注销订阅、取消仍依赖来源的任务；不清空其他来源已并入的公共护体。
- 返盾是否含护体吸收量、阵法费用、撤阵与持续方案仍是待选择/工作默认，迁移或测试不能偷偷替作者定案。

必须用两种互不混同的样例检验时点：一击多目标共同提交；连续两击之间在约定边界处理响应。自动任务内部的子响应处理还要保持原基线顺序，任何差异都作为规则改动记录。

| 层次 | 能证明什么 | 不能冒充什么 |
|---|---|---|
| 原件/源码字节校验 | 指定来源文件完整且未悄悄改写 | 项目已经在新仓、代码已经运行 |
