## 1. 采用身份与唯一性

作者最新明确意见优先。本文区分：**已采用方向/规则、首版执行默认、试验参数、已认可待实现、待选择、历史撤销**。一项设计被认可，不等于代码已经具备。旧版文档、报告和测试按自己的版本保留，不能合并成一套不存在的规则。

本仓总纲负责总入口。结算协议与模块职责由[战斗结算内核](战斗结算内核.md)维护；阵法由[阵法技能](阵法技能.md)维护；理由及纠错见[讨论沿革](讨论共识与演变.md)。后续实施后更新这些原件，不在旧游戏仓继续维护同名现行规则。

## 2. 体验目标与训练营范围

**已采用：**战前组织本领，战中作出应变，修炼和熟练使同一门法能发挥更强。允许普通战展示成长和熟练，重点战检验目标、顺序、资源、准备与对手节奏。操作更精细应有机会改善胜负或消耗，但“以弱胜强、高手AI、各流派平衡”是验证目标，不是已经证明的结论。

训练营流程：选人物 → 自由合法搭配功法与法宝 → 右下角进入训练营 → 镜像或预设 → 确认 → 战斗 → 原条件重试或返回配装。取消选战不丢配置；开战才冻结最新配置；重试恢复开局，不使用上场结束时的临时装配。

镜像复制实际成品、参数、位置、法宝和造诣输入；难度同时改变基础实力与AI。普通镜像同数值，简单较低，困难较高；已发布首版用Hmax/S做变化，M/Q保持以免复制配置违法，这是工作默认。预设野怪/NPC独立，不因玩家改装暗中生成克制。纯AI测试另锁人物、装备和先手条件。

不制作经验积累、获取、经济、探索或完整灵宠玩家界面；全部开放的是已经制作并校验的测试成品，不是任意公式和未定义特殊效果。保留固定成长快照，用来验证公式，不冒充完成养成。

## 3. 人物、本领与四种计数

气血H/Hmax、当前灵气E/上限M、回气Q、速度S继续存在。御气造诣：控御负责合法目标，节用负责用气，凝练负责效量，分化负责有限执行结构。没有新增“锋芒”第五属性；此前该试称由凝练/P承担。

- **公共刻t**：只有没有活动窗口及待处理响应时推进。自然回气、行动进度、周期状态、战机自然增长使用它。
- **普通行动A**：由速度推动，满条只获得普通行动资格。普通回合结束重置，战机不清空它。
- **全部自身窗口W**：真正进入普通或战机窗口才加1，用于技能CD及阵法成阵等待。战机计一次W，不按其中施法次数计数。
- **自身普通回合R**：只进入普通回合才加1，绑定明确的普通周期效果。
- **战机Z**：独立于A，满条登记额外窗口资格；不是普通技能额外必须等待的第二道门槛。

动作、施法、攻击段数、目标数不增加W/R。法宝自动发动不算主角主动施法，灵宠行动只推进其自身计数。逻辑时间、动画时间、玩家思考时间分开。

## 4. 普通与战机窗口

**已采用：**普通回合只有一次主动主动作，功法、基础挥剑、主动《催》择一。战机回合可连续使用不同的合法就绪入口，不免除费用、条件、目标或CD。每门入口每窗最多一次；一窗内连续施法不再推进CD。

已发布工作默认：四个通用功法格，每窗口主动作前至多一次准备换法，不占主动作但锁住换入格本窗操作；战机也不允许无限翻库换法连用。换法同时遵守承载和同源限制。

CD最低1，普通主动功法基础CD=N（标准功能句数）。本窗口W施放，登记恢复窗口W+CD；CD1在下个自身窗口恢复。格子与同源法门等待同时检查较晚者，卸下、换名、跨格不洗掉债务。不同功法同CD档不因此共享整类CD。

战机只在安全调度点开启，不切断正在执行的技能或窗口；不自动补满灵气，不刷新全部CD，不推进公共刻，不重触发全部普通回合效果。玩家能查看并结束战机，不被自动强制施法。

战机基础随刻积累，普通主动行为的有效成果可提供额外收益；按根动作汇总并限额，不按多段/多目标免费倍增，不奖励过量、自伤或自动后代。战机动作及其后代不能自养下一战机。已发布安全默认：最多一份待执行资格；战机后至少完成一次普通回合才能再次兑现。具体速度、奖励、上限均为试验值。

### 4.1 战机争夺：目标已提出，机制仍待设计

作者确认战机属于奖励机会，计一次W；但“独立进度条满后多次出手”尚不足以确立最终体验，希望玩家有主动争取战机的感觉。战机如何累积、双方如何影响取得时点、是否存在共享机会或争夺目标，均未定稿。本节前述3.0.1积累与安全锁是现有试验基线，不因本轮讨论直接替换代码，也不当作最终平衡。

后续讨论应先确定争取对象、产生资格的条件、可采取的争取/应对行动和先取得资格的价值，再调收益系数。共享条、扣除对手战机、破绽标记、争夺胜方额外加成均未获采用，不由“抢战机”一词自动推导加入。自然积累与有效战果的权重、防守准备的可用路径、速度和多段的重复奖励、奖励自我循环，属于需对局验证的问题。该未决模块不阻塞按W运行的阵法接口。

## 5. 功法规则句与成长

标准功能句是：在明确时点与条件下，对明确目标执行一种公共基础作用，产生可引用结果。条件、读取、算术不额外计句；实际新增的独立作用/执行参与N。文案分句与代码行数都不是计数标准。

伤害＋施加侵袭是两句；按第一句实际损失施加侵袭仍是两句；消耗印记再造成伤害也是两个真实作用。独立重复两次攻击与一次攻击多个目标必须区分。现行一至三句容量是测试内容边界，不自动扩为无限结构。

功法数据分层：整次施法记录前提、目标方案、基础费用、结构、N/CD；各句记录操作、条件、目标、效量表达式、读取时点、成长绑定与结果；公共Buff独立维护叠加、消退、防护和触发定义。

当前操作基础：damage/heal/qi/apply/remove/consume。扣气血支付不是伤害，不能用任意字段加减绕过伤害、防护、死亡或来源规则。

成长来源分开：功法基础和转化系数、人物凝练派生效能P、系列熟练、本法熟练。首版直接效量采用 `(基础值+系数×P)×(1+系列加成+本法加成)` 的明确取整版本；精确参数为试验表。同一门法不同保存方案共享本法造诣身份，广义系列与同源法门不是一个ID。

已有句的数值增强不自动增加N、CD或费用。主动选择更大投入、更多目标或独立执行是新方案，检查相应资格与费用；旧方案保留。派生句读取前句实际结果，不重复乘同一份凝练/熟练；目标数、执行数、条件门槛、时长与百分比不默认随通用效量一起放大。

## 6. 法宝自动功效与独立《催》

**作者明确纠正：保留两条能力，禁止入口串用，不删除《催》。**

自动功效只接受声明事件，图标供查看，不能从手动命令重放auto数组。不支付主人即时H/E、不消费主人锋锐、不占主动作、不推动主人W。自动直接伤害仍接受对方适用防护。

《催》是独立active成品，拥有自己的效果、费用、CD和本窗使用记录，不占四个功法格。普通回合占一次主动作；战机可与其他入口连用。它由持有者主动施展，正常应用撕裂/逆气/凝神，含本人直接攻击时应用本人锋锐。自动事件计次与《催》使用/CD互不清理、互不锁定；同窗各自合法发动不是重复Bug。

没有active的法宝不生成催动候选；禁止把auto当默认主动回退。自动开关只控制自动部分。低血保护按明确的敌对实际受伤且存活后触发，不倒救致死伤，不因气血支付触发。

灵宠是独立单位，有自己的资源、A/W/R与能力。主人减益不能让灵宠替主人支付；灵宠自身减益正常生效。自动控制不意味着全面免疫减益，也不要求系统保证所有自动行为永远最优。

## 7. 公共结算与现行Buff

一次施法：预览 → 核验 → 支付/动作/CD提交 → 依次执行功能句与效果组 → 边界响应 → 收尾 → 交还窗口。开始核验失败不部分扣款；已提交后，后句失败保留已经发生的结果。H必须大于气血Cost，E至少等于灵气Cost。

同一次多目标攻击共同读取、共同提交；连续两次攻击是两个组。伤害请求、护体吸收、实际气血损失、过量各自记录。公共刻伤害与恢复从同一开始快照计算净收支，再同组判生死，不因遍历顺序提前死亡。已结束战斗不启动新窗口和需存活的保护。

| 公共状态 | 基线语义与时钟 |
|---|---|
| 护体 | 每层吸收1点直接伤害，总池不超过Hmax；不挡效果伤害或支付，不自然衰减。 |
| 锋锐 | 本人独立直接攻击获得受基础量上限约束的加成，整次攻击后减1层，不按目标重复消耗；自动法宝不借用。 |
| 神速 | 提高每公共刻A增长，不直接改速度排序或Z自然增长。 |
| 凝神/逆气 | 分别减少/增加一次主动施法灵气费用，最低0，不改变CD。 |
| 鲸吞/滞气 | 修正每公共刻自然回气，当前最低1；不使已装法宝失效。 |
| 回春/侵袭 | 每公共刻分别按当前层数恢复/造成效果伤害；回春减1，侵袭减半向下取整；使用公共净结算。 |
| 蚀骨 | 仅自身普通窗口前，每层造成当前气血1%的效果伤害；战机前不触发。 |
| 撕裂 | 增加一次主动施法气血支付，仅普通回合结束减半。 |
| 无常印记 | 无独立效果，由明确规则读取或消耗；不冒充第12项基础Buff。 |

神速等尚无最终生命周期的状态沿用基线本场保持/明确清除默认，不能无记录地统一改成倒计时。暂停或废弃的基础免伤、格挡、易伤等不因历史文章提及自动恢复。

## 8. 阵法与结算内核的新增方向

**已认可待实现：**阵法是布阵→等待→成阵→持阵的分阶段能力。布阵等待结束才启用持续阵势；持阵为立即生效后进入自身CD的普通主动能力。两个阶段不等于一次施法里的两条功能句，也不意味着所有技能在CD结束时自动执行效果。

**作者本轮已确定，待实现：**龟甲阵仅按实际气血损失返50%护体；布阵等待3个全部自身窗口，W布阵、W+3成阵，战机计一次；持阵CD1，增加当前护体50%。布阵与持阵分别有独立灵气消耗。阵势无特殊说明时永久，即本场不自然到期；主动换走无论成阵前后均取消/撤阵，灵气不退；同名不能叠加。

阵法用于长线投资：成型后应在适用条件下取得高于同灵气普通能力的效率或更好的长期累计效果，但需要把前期灵气、主动作、等待和撤阵风险计入总成本。两阶段的具体报价、装配承载映射及异名并存尚未定稿；死亡/终局清理按专题区分公共规则与工作默认。见[阵法现行规则与剩余事项](阵法技能.md)。

**已认可待实现：**从当前统一执行器整理出固定流程＋资格检查、数值修正、事实响应、时钟/延迟任务四类接口。普通新Buff以定义或小模块接入；新打断、复活或时钟权限仍是协议变更。详见[结算内核](战斗结算内核.md)。

## 9. AI、可解释性与验证

AI强度拆成构筑质量、战中决策和数值实力。简单固定顺序但合法；普通识别有效收益、溢出、支付和简单配合；困难有限比较窗口计划及合理对手回应，不读未来点击。预演和实战使用同一个执行器，状态副本隔离，截断不冒充完整预测。

结果要能解释：为什么付出这些费用、为什么这格不能用、哪种防护生效、哪个触发失败、联动读了哪个实际结果。记录root_action/cast/sentence/group/event和所有者、执行者、来源、支付者。图形帧、动画完成回调和AI线程不推进逻辑规则。

小尺度训练人物约数百血只是当前试验输入。缩尺不能机械除以十：Buff层数可能同时影响次数/持续量，Q又关联系统额度。同层、同预算、短长战、首轮爆发和未决局面都需对照。测试通过不是好玩、总体平衡或人类AI难度证明。

## 10. 后续工作边界

完整3.0.1工程已经合入本仓main。作者要求结果导向：优先实现已讨论的未实现能力，旧资料按需补录，不作为功能开发和新版本发布前置。下一交付目标为可操作的阵法及其必要结算接口，不先制作无限扩展框架。行为等价重构、阵法新增与数值重定标分开验收，不能只交模块文件就视为玩家功能完成。

单句、双句、三句法的相对价值由相同人物/预算、不同战斗长度、普通与战机条件下的真实对照测试决定；讨论不预先宣判哪档必然强。战机争夺机制另行研究，未采用前保留现有基线。本轮仅更新设计采用状态，没有实现阵法或重构代码。

作者更正优先级尤其包括：不能再删除独立《催》；不能把旧公共刻CD搬回来；不能把现今普通单主动作误写成每个普通窗口不限施法；不能把阵法方案中的待选择项写成既有实现。
