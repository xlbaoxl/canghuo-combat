# 网页托管：直接使用公开仓库与 GitHub Pages

## 当前采用

2026-10-10，作者已将 `xlbaoxl/canghuo-combat` 改为公开，并明确要求部署。停止依赖 Vercel、手机号注册、ChatGPT 插件和私密托管。现有仓库就是源码、测试与网页发布的唯一入口。

自动链路：`main 提交 → 原规则/表现/线程/固定对局 → 原浏览器回归 → Pages 适配 → 无响应头子路径真实浏览器回归 → 同一产物发布 GitHub Pages → 实际 HTTPS 完整对局验收`。PR 只构建与验证，不覆盖试玩站点。

## GitHub 首次设置

仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。工作流会尝试正常启用 Pages；若 GitHub 拒绝工作流令牌进行首次管理设置，需要仓库所有者在这里选一次，随后重新运行失败的 pages job 即可。无需另注册平台、下载工程、安装 Godot 或提供密钥。

预期地址为 `https://xlbaoxl.github.io/canghuo-combat/`；只有 Pages 部署返回的网址及实际检查成功，才能称为已上线。本文提交时首次部署尚待执行，不把这个可推导地址当作成功证据。

## 浏览器适配

复用原始 Godot 导出，不改 PCK/WASM、AI、数值、素材或桌面工程。`tools/web/pages.py` 先核对全部原导出文件和构建证据，再为生成的 HTML 加载独立的隔离脚本，并更新实际文件清单与构建回执。

`index.isolation.worker.js` 只在 `/canghuo-combat/` 作用域对本站 GET 请求添加 COOP/COEP/CORP 响应头，不建立离线游戏缓存。首次启动最多进行一次初始化刷新，游戏启动后不自动刷新；无法建立环境时明确报错。更新仍由玩家确认，不把旧缓存当作最新版。

配装仍保存在当前浏览器的原 IndexedDB 中。刷新不会续接战斗运行态，只恢复合法配装与冻结的重试初态。诊断可下载，不自动上传。

## 测试与真实完成标准

保留原 46 点浏览器回归，新增无服务端隔离响应头、项目子路径、首次自动初始化、线程 AI、自然战机、多门施法、独立《催》、中止/重试、完整对局、反馈下载、刷新保存及更新提示测试。公开网址再次核对清单中全部文件的实际字节与运行中的提交身份，不能只验证 HTTP 200。

Pages 发布是普通公开静态网站，资源可下载；没有额外访问保护。来源许可文件和既有研究归档边界保持原样，不因公开而宣称新增开源许可证。

`web-playtest-site` 作为过去 Vercel 方案的历史产物保留，不删除、不强推、不再自动同步。Vercel API 通道不再由主工作流执行，避免双通道发布。现在的 workflow 不受旧同步器“必须私有”的条件影响。

Firefox/Safari/手机和作者在中国大陆网络及设备的实际体验，均需另行验收；云端 Chromium 成功不等于这些环境全部通过。

官方依据：[Godot Web 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)、[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
