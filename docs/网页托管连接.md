## GitHub 首次设置

打开 `https://github.com/xlbaoxl/canghuo-combat/settings/pages`，在 **Build and deployment → Source** 选择 **GitHub Actions**。不必创建 Jekyll/Hugo 等模板工作流，现有 `.github/workflows/web-playtest.yml` 已提供构建、发布和实际网址验收；也不要再选择旧 Vercel 发布分支。

不需要新平台注册、下载工程、安装 Godot、命令行或在聊天提供密钥。仓库公开与开启 Pages 是两个不同的设置，前者已经确认完成。

预期网址是 `https://xlbaoxl.github.io/canghuo-combat/`。目前只是由账号/仓库名确定的目标，不是已上线链接；以实际 Pages 返回的网址和 HTTPS 浏览器验收为准。

## 自动发布链路

`main 提交 → 原规则/表现/线程/固定对局 → 原浏览器回归 → Pages 适配 → 无响应头子路径真实浏览器回归 → 同一产物发布 GitHub Pages → 实际 HTTPS 完整对局验收`。PR 只构建与验证，不覆盖试玩站点。只读文档更新不自动重建游戏，页面中的构建提交指向实际测试与发布的运行版本。

## 浏览器适配

复用原始 Godot 导出，不改 PCK/WASM、AI、数值、素材或桌面工程。`tools/web/pages.py` 先核对全部原导出文件和构建证据，再为生成的 HTML 加载独立的隔离脚本，并更新实际文件清单与构建回执。

`index.isolation.worker.js` 只在 `/canghuo-combat/` 作用域对本站 GET 请求添加 COOP/COEP/CORP 响应头，不建立离线游戏缓存。首次启动最多进行一次初始化刷新，游戏启动后不自动刷新；无法建立环境时明确报错。更新仍由玩家确认，不把旧缓存当作最新版。

配装仍保存在当前浏览器的原 IndexedDB 中。刷新不会续接战斗运行态，只恢复合法配装与冻结的重试初态。诊断可下载，不自动上传。
