# 阵法技能：布阵、成阵与持阵

> 1.0｜2026-10-09｜状态：作者提出、方向认可；**尚未进入3.0.1执行器**。
> 本文保留作者原意，区分建议默认与待选择项。来源为本会话，不冒称其他游戏既有规则。

## 1. 作者原始构想

阵法是不同于普通技能的功法类型。使用布阵后进入等待，等待结束才出现阵法效果；随后该技能入口转为持阵。各阶段有不同CD。

龟甲阵原始例子：

> 布阵：CD3，受到直接伤害时，获得50％伤害量的护体。持阵：CD1，获得当前护体层数50％的护体。

这里“受到直接伤害返盾”属于**成阵后**的持续阵势，不在最初按下布阵时立即启用。持阵是主动使用后立即生效再进入CD1，不是再等一个窗口才结算护体。

## 2. 为什么需要独立类型

普通技能：支付 → 立即执行效果 → 等待恢复使用资格。

阵法布置：支付 → 创建待成阵任务 → 到期自动激活阵势并转换入口。

持阵：支付 → 立即执行持阵效果 → 等待再次持阵。

延迟成阵与普通回转不是同一职责。不得全局增加“CD归零就执行技能效果”；不能为了凑CD3给布阵塞三句无关作用。布阵和持阵是不同时间的阶段，不等于同一次施法里的两条规则句。

对普通法继续CD=N；阵法模板单独声明成阵延迟，持阵自身按正常规则句/回转处理。

## 3. 状态机与时钟建议

`未布阵 → 布阵中 → 已成阵/可持阵 ↔ 已成阵/持阵回转中 → 撤阵/失效`。

**建议默认：**成阵延迟使用全部自身窗口W，普通和战机都推进。W=1布阵，成阵窗口为1+3=4；W=2、3仍在等待，W=4开始的到期步骤自动成阵，并开放持阵。持阵当窗可以使用，使用后ready=W+1；自动成阵不额外占主动作，也不再推进W。

若以后某阵专门使用普通回合R，必须明确写“普通回合”，不能同名CD3暗用另一时钟。受控算例不能换算成固定秒数或公共刻数。

布阵不是连续引导。等待期间可以使用其他本领；它是一个已完成部署动作产生的待办任务，不让原始施法调用栈跨多个回合悬挂。

成阵时点建议位于：窗口前存活检查 → W增加/本窗操作记录重置 → 到期任务 → 对应窗口开始效果 → 主动选择。它不倒退保护普通窗口前已经结算的蚀骨。

## 4. 返盾的数值口径仍需明确

作者说“50％伤害量”，尚未明确是否包含已有护体吸收。两者都保存，不把建议包装成作者已经逐项定案。

假设已有40护体，承受100直接伤害且气血足够：

| 方案 | 本次基数/返盾 | 玩法含义 |
|---|---|---|
| A：实际气血损失 | 60 / 30 | 本体受伤后形成保护，全吸收时不返盾 |
| B：有效承伤含护体吸收 | 60+40 / 50 | 旧护体承担的攻击也可以补回一部分 |

推荐先验证A，正式采用前标记为试验方案。B不应使用包含过量伤害的原始请求量；若选择B，应在文案明确“包括护体吸收部分”。

任何方案：本次伤害先结算，存活者再获得护体；不倒扣已经发生的伤害，不靠受伤后效果复活。气血支付不等于伤害，公共效果伤害不等于直接伤害。是否只接受敌对来源建议明确为是，避免自伤刷盾。

按每次独立伤害组的确定结果响应。同一阵势对同一事件最多一次；一击多个目标与多击同目标保持不同作用域。连续两击：第一击结果 → 合法返盾响应 → 第二击。阵势不得自己实现扣血或防护算法。

## 5. 持阵：一次读取、一次增量

建议定义：持阵效果组开始时读取自身当前护体，按50％请求增加护体，遵守公共整数取整和总池≤Hmax。

40层变60层；0层仍为0。一次持阵不会反复读取增加后的结果。当前护体本身已经含成长或其他效果，不默认再把派生量乘一次凝练/熟练。比例研究若开放，需要独立且明确的研究参数。

布阵费用与持阵费用分别定义，作者尚未给数值，不在此填写虚构报价。主动布阵/持阵承担主动支付与动作权限；自动成阵/返盾不是主角再次施法，不二次扣撕裂或逆气等费用。

“持阵”在当前构想中是主动强化，不默认成为每回合不点就崩阵的维持税。要设计持续耗气、每回合续阵或站桩引导，属于另一项明确变更。

## 6. 阵势实例与失效建议

实例至少保存：definition/instance、所有者、保护对象、来源功法/格子、创建W、到期W、阶段、激活监听、依赖任务、版本、执行参数快照。

建议首版工作默认：

- 同名不重复注册，同一来源不能多份返盾叠加。
- 从原格换走，取消布阵任务或撤下阵势；已付费用不退，格子/同源等待不清零。
- 死亡、战斗结束或明确撤阵时，注销监听并取消依赖任务；到期时再核验来源仍有效。
- 撤阵不倒扣已经进入公共护体池的层数，不能误删其他技能/法宝贡献。
- 暂以本场持续至明确失效为试验默认；最终持续期、自然衰减、破阵机制另定。

这些限制解决卸下后仍永久享受无限阵法、图标消失监听仍在、读档重复注册等问题，但未经正式采用不能把它们宣称为既有作者原话。

新定义与运行态都要进入版本化快照。初版可以只在安全决策边界保存；若不支持布阵中的局面续读，应明确拒绝，不把旧档当新状态自动激活。

## 7. 与战机、格子、法宝和AI的接口

布阵和持阵占普通主动作；战机按入口限制使用，不在同窗重复持阵。战机推进W可以加快成阵，这是采用W的明确收益，不是偷偷刷新CD。

布阵阶段持阵入口不可用，阵成后不占第二个功法格。按阶段显示剩余等待、当前持续作用、持阵费用与CD，避免玩家把CD归零误读为自动再加一遍护体。

法宝依然自动＋独立《催》，阵法不是删除催动的理由。灵宠仍有自己的行动归属。谁造成了触发所依据的伤害，与谁获得返盾分别记录。

AI预演必须复制待成阵任务、阵势实例和阶段；不能只评价布阵当下“没有伤害”而将它视为白花费用，也不能在短期观察不到成阵时虚构确定的长期收益。若短视范围不足，用公开、标明范围的价值估计和完整对照测试，不偷看玩家未来输入。

## 8. 需要验证的价值与风险

布阵放弃当前一次进攻/恢复，等阵形成再获得持续作用；持阵继续在护体强化与其他主动作之间取舍。普通回合稀缺行动与战机集中施展可以让这种部署有意义。

但不能凭等待3次就认为已经平衡。短战可能用不上；只靠拖长血量不能证明它有用。持阵50％是复利：无消耗/攻击/上限干扰时40→60→90→135，不是固定增量。保持作者原50％作为测试点，结合费用、上限、攻击通道、对手行动与战斗长度观察，不先暗改倍率。

## 9. 待定矩阵与接入门槛

| 项目 | 身份 | 开发要求 |
|---|---|---|
| 两阶段、延迟成阵、持阵即时后CD | 作者构想/认可方向 | 必须保留，不能改成先立即返盾 |
| 布阵3、持阵1、两项50％ | 作者样例 | 可作为首个测试输入，不代表已平衡 |
| W+3成阵，W含战机 | 推荐执行口径 | 显示精确时间线；选择R时必须显式变更 |
| 返盾A或B | 尚未逐项确认 | 分开配置测试，不混写成同一公式 |
| 布阵/持阵费用 | 未给定 | 内容制作前填写并标试验值 |
| 持续、换走撤阵、同名限制 | 建议默认 | 保留失效理由，不让程序无记录决定 |
| 被驱散/打断/反制 | 待设计 | 不凭系统存在监听就宣布开放 |

最低用例：布阵当窗无效果；W+2未成、W+3恰一次成；成阵可持；无双重支付；自动成阵不占主动作；战机推进等待但不循环；CD1不允许同窗重复；全吸收/实际损失/致死/效果伤害/气血支付分别判定；两击间返盾；0盾持阵0收益；护体上限和取整；撤阵/死亡/换格/读档不留下幽灵监听；AI副本不污染真实任务。

本轮是设计归档，没有新增实际阵法内容，也没有给这组用例记通过。
