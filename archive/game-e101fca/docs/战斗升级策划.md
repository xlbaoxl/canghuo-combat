## 0. 采用边界与文档权威

### 0.1 本文要完成什么

本次升级把训练营从“每次个人窗口都能连续使用多门法”，改成“普通回合慎重选择一次主动行为，战机回合集中施展多门本领”。同步解决自动行为的归属、人物和功法的成长联系、数值阅读尺度，以及时钟、阶段、事件、支付和结算边界。

核心体验：**战前组织本领；普通回合选择与准备；战机到来集中兑现；对手根据同样规则应对。**

本文不是原作机制复刻，也不是在原代码后面增加一批特例。后续应改掉冲突定义与执行路径，不保留两套互相矛盾的当前规则。

### 0.2 三种不同的采用身份

| 标记 | 含义 | 执行要求 |
|---|---|---|
| **共识** | 本窗口作者明确提出并接受的方向，或未被推翻的既有规则 | 实施不得为了省事恢复旧方案。 |
| **首版执行默认** | 将讨论补成可编码协议的选择；不是已经实测的最优解 | 在本轮版本内确定执行；调整须改本文对应定义、参数和测试，不由各模块自行选择。 |
| **试验参数** | 用来启动测试的数值、预算与内容样本 | 可以定标替换，必须记录输入版本；不得称为正式成长表或平衡结果。 |

本文中的具体队列顺序、安全锁、奖励系数、熟练加成表等，凡未由作者逐项给出，均按“首版执行默认／试验参数”登记，不倒推成作者早已确认的事实。

### 0.3 与已有材料的关系

优先级为：**作者后续明确指示 > 本文明确覆盖的升级定义 > 未冲突的《新版战斗.md》定义 > 历史方案、旧测试与实现。**

本文是这次升级的专题实施依据，不新增第二套长期并行的底层规则。入仓实施时，在《新版战斗.md》相应章节改成新定义或转引本文唯一小节；废止的段落只保留历史说明，不能一边写“一窗多法”，另一边写“普通回合一招”，还同时标为现行。

本文没有修改仓库、游戏、世界设定或线上发布。后续动代码前核对最新分支、`AGENTS.md`、本地未提交内容及作者并发修改；使用含现有训练营代码的基底，不从历史文档分支另造一个不相连的Demo，不覆盖既有UI改进。

## 1. 交付范围：升级训练营，不扩成完整养成游戏

### 1.1 保留的玩家流程

**选人物 → 配装功法与自动法宝 → 配装页右下角进入训练营 → 选镜像及难度，或选预设野怪／NPC → 确认开战 → 结算、原条件重试或回配装。**

不在配装之前强制选难度。关闭选择窗不丢配装，不发生入场效果。开战时重新校验并冻结最后确认的快照。

首版保留4个预设人物、4个通用功法格、2个法宝位、开放全部已发布合法成品。数量是训练营规模，不是正式世界的永久限制。

### 1.2 镜像与预设

镜像复制成品蓝本、版本、公式、位置、法宝及熟练输入，不复制一组脱离角色状态的最终伤害常数。每一方按自己的真实属性解析效果，运行状态相互独立。

镜像三档继续同时改变Hmax／S与AI。80%／100%／120%保留为试验倍率；M、Q与默认造诣、熟练保持相同，避免复制的满载配装非法。不得靠隐藏的伤害、命中或费用特权制造难度。内部研究AI能力时，另锁住数值与配装，仅换策略。

预设敌人读取自己的数据和行为，不根据玩家最后的配装临时生成克制。敌人的战机、费用、CD、自动行为与玩家走同一执行器。

### 1.3 本次不做与必须做

不做升级积累、熟练刷取、功法解锁、掉落、经济、探索、捕捉繁殖、任意规则句编辑器和完整灵宠玩家流程。

必须做人物效能、系列熟练、本法熟练的**结果输入和计算**，用固定快照检验成长关系；不以“不做养成过程”为由继续让这些字段不生效。

灵宠本次先完成独立单位的规则归属与内核夹具，不强制增加宠物养成和新界面。主流程仍以双方主战角色为主，保留可扩展的多单位和多目标规则。

完整交付要能实际配装、操作普通回合、经历战机、看懂效果与消耗、结算重试。公式测试、截图或AI互搏不单独替代可操作过程。

## 2. 术语、时钟与状态：禁止再用一个“回合”指所有事情

### 2.1 三种时间计数

| 名称／建议字段 | 增加条件 | 驱动内容 | 不由什么推进 |
|---|---|---|---|
| 公共刻 `t` | 当前没有活动窗口、待处理效果和可调度机会时，推进一次逻辑时间 | 自然回气、普通行动条、战机自然积累、公共刻状态 | 动画帧、现实思考时间、每次命中、每个单位的窗口 |
| 自身全部窗口编号 `W` | 实际进入一次普通或战机窗口，增加1 | 主动技能CD、每窗口入口使用记录 | 本窗多次施法、独立段数、他人／宠物行动 |
| 自身普通回合编号 `R` | 实际进入普通窗口，增加1；战机不增加 | 绑定正常行动周期的状态、自动法宝和安全锁 | 战机窗口、反击、自动攻击 |

“普通回合”与“战机回合”都是自身出手窗口，但只有前者属于普通周期。“一次施法”“一次独立攻击”“一个功能句”都不是回合。

### 2.2 两条进度

| 字段 | 含义 | 首版范围与来源 |
|---|---|---|
| `action_progress`，简称A | 普通行动进度，承接旧J的行动用途 | 0—100，速度相关的每刻增长 |
| `opportunity_gauge`，简称Z | 战机值，蓄满后取得一次额外窗口资格 | 0—Zmax，自然增长＋合格战斗事件 |
| `opportunity_pending` | 已登记、尚未执行的战机资格 | 每单位至多一个 |
| `opportunity_locked` | 上次战机后是否尚未完成一次自己的普通回合 | 不准连续兑换；不等于暂停普通行动条 |
| `window_kind` | 当前活动窗口类型 | `NORMAL`或`OPPORTUNITY` |

界面“行动条”和“战机条”必须显著区分，不能两个都叫战机。旧Buff神速修改的是普通行动条增长，不默认同时加速新增Z。

### 2.3 角色与入口基础记录

保留H/Hmax、E/M、基础Q、有效S、公共Buff池、装备、造诣、熟练。新增／调整：

- `W`、`R`、`window_id`、`window_kind`、普通主动作是否使用；
- 每格成品、`ready_window`、本窗状态；
- 同源法门尚未到期的`family_ready_window`；
- 战机进度、资格票据、登记时点、安全锁；
- 自动触发实例标记、当前阶段、队列和事件序号。

所有实体有稳定实例ID。蓝本同源ID、系列熟练ID、窗口ID、施法ID、功能句ID不得相互替代。

### 2.4 独立训练的初始状态〔首版执行默认〕

确认开战后，H=Hmax、E=M、A=0、Z=0、W=0、R=0；普通主动作与各入口使用记录清空，格子及同源恢复窗口初值为1，战机无票据且未锁定。除测试场景显式声明外没有初始Buff；全部单位建立完毕后，才结算入场法宝。

双方主战人物`opportunity_enabled=true`，使用同样的Z规则；不是只有玩家能进入战机。灵宠本轮默认false，仅因其尚未进入该玩法范围，不代表它替主人提供额外机会。

人物能力、熟练和成品在冻结快照前完成校验；基础攻击同样绑定明确的人物效量表达式或测试输入，不保留一个未随尺度检查的隐藏100点伤害。基本施法与装备列表均不得读到上场运行态。

## 3. 普通回合、战机回合与技能CD

### 3.1 主动权限表

| 行为 | 普通回合 | 战机回合 |
|---|---|---|
| 主动功法 | 一次成功施法即用掉本回合主动作 | 可依次施放多门已就绪法；每格本窗至多一次 |
| 基础挥剑 | 与施法竞争同一个主动作 | 独立基础攻击入口，本窗至多一次 |
| 法宝主动《催》 | 与施法、挥剑竞争唯一主动作；单独支付并登记本入口CD | 不受全窗一次总上限限制；每件《催》本窗至多一次，仍受费用与CD限制 |
| 换法 | 首版默认：主动作前最多换一格，不消耗主动作；该格本窗不能施法 | 同样最多换一格，占该格本窗操作；新法当窗不可用 |
| 用药 | 首版主流程不新增；若保留已有药品，必须与普通主动作共用额度 | 有内容时至多一次，按声明支付；不得临时变成无限补气 |
| 结束 | 可不采取主动作直接结束 | 随时结束，不强迫用完全部技能 |

“换法每窗最多一次、作为准备操作”是为保留临场调整又限制翻库劳动的**首版执行默认**，不是新增行动点资源。它替换旧的多格可同时换法自由度，后续可以对照调整，不能含糊并存。

普通主动作成功提交后，完成整次作用及自动响应，进入普通回合收尾，不再开放第二次施法。失败指令不消耗主动作。

战机的“不受限”只解除“一次主动作”的总量上限，不免除费用、CD、合法目标、使用条件或每格操作限制。四功法格＋一次基础挥剑给出有限上界；换入新法不能增加这个上界，不提供任意全库轮换连放。

### 3.2 CD口径〔本次统一定义〕

`CD`为正整数，普通主动法当前按标准功能句数生成：

```text
CD = N，N >= 1
施法成功开始时：
    slot.ready_window = W + CD
    family_ready_window[source_family_id] = W + CD
```

| N／CD | 在W=1施放 | 最早再用 |
|---:|---|---:|
| 1 | 本窗不能再用 | W=2 |
| 2 | 下个窗口仍在冷却 | W=3 |
| 3 | 接下来两个窗口仍在冷却 | W=4 |

不再对玩家显示旧k=0／1／2；旧k只是迁移关系`CD=k+1`，不是当前执行第二个减计数器。旧版本本来使用`ready=W+N`，本次不能误改成`W+N+1`。

W只在进入窗口时增加一次。窗口内每施一招、每段、每个目标、窗口结束都不另减CD。

### 3.3 战机算一个完整CD机会，但不刷新所有技能

进入战机：W增加1，R不变。CD=1技能可在相邻的普通窗口与战机窗口各用一次；CD=2／3仍需等到登记的W。战机入口不把所有`ready_window`设为当前W。

这意味着CD=1不保证经过一个“速度决定的普通行动间隔”；它保证至少到**下一个自己的出手窗口**。战机就是合法提前带来这个窗口的来源。

没有实际进入的机会不增加W。空操作但正常进入后结束的窗口仍计W；窗口前死亡不计。首版不开放眩晕跳回合、复活、额外窗口叠加等尚未定义的情况。

### 3.4 双约束防止换格绕CD

施用必须同时满足：

```text
本角色当前有主动决策权
本格当窗未操作
W >= max(slot.ready_window, family_ready_window[该法同源ID])
整门前提、目标、全部开始费用合法
```

换法保留目标格的原恢复窗口，不清除任何同源记录。即使某门法当前没有装在任何格里，其未到期的同源等待仍存在。该规则与“当前四格不能同时装同源多版本”同时生效。

换入后的最早可用窗口预览为`max(W+1, 本格原恢复窗口, 新法同源恢复窗口)`。不显示笼统的“下回合一定可用”。

同系列的不同法门不共享等待，同CD档也不共享等待。同源ID用于防别名／版本中转，不扩大成职业或回转类别锁。

### 3.5 普通进度与战机窗口相互独立

普通窗口结束：A归零。战机窗口结束：A保持原值。两类窗口内公共时间都暂停，不因多打几招自然回气，也不因玩家阅读更久积累进度。

若A已满且Z也取得资格，按第4节先后调度；战机不能吃掉已取得的普通机会。可能出现“战机之后紧接普通出手”，是两次真实机会，不等于同窗刷CD。需在平衡测试中保留这个边界。

## 4. 全局阶段与行动调度

### 4.1 阶段权限表〔首版执行默认〕

| 阶段ID | 处理内容 | 接受新的主动战斗指令？ |
|---|---|---|
| `INIT` | 校验开战快照，建立全部单位、数据、固定顺序 | 否 |
| `ENTRY_RESOLVE` | 按固定顺序结算入场自动效果 | 否 |
| `DISPATCH` | 只调度合法机会，不修改技能效果 | 否 |
| `PUBLIC_TICK` | 共同快照计算并提交一个公共刻 | 否 |
| `WINDOW_PRE` | 普通窗口的窗口前状态与存亡检查 | 否 |
| `WINDOW_OPEN` | 建窗口、增加W／必要时R、重置入口本窗记录、处理开始事件 | 否 |
| `DECISION` | 查看、选动作、选目标、提交或结束 | 仅当前控制者可以 |
| `ACTION_VALIDATE` | 最后核验动作与全部开始成本 | 否；失败返回DECISION |
| `ACTION_COMMIT` | 原子支付，登记主动作／格子使用／CD | 否 |
| `EFFECT_RESOLVE` | 执行有序功能句和结算组 | 否 |
| `RESPONSE_DRAIN` | 执行当前边界允许的自动响应队列 | 否 |
| `ACTION_CLOSE` | 封存整次施法结果与行为战机奖励 | 否 |
| `WINDOW_CLOSE` | 普通或战机专属结束、进度与安全锁处理 | 否 |
| `BATTLE_END` | 一次性封存胜负、统计、取消待执行机会 | 否；仅结果页操作 |

暂停、倍速、查看说明可以作为表现层操作，但不能跳过阶段修改战斗状态。一次玩家已提交行为不得被其后一帧的第二个点击插入。

### 4.2 主循环

```text
INIT → ENTRY_RESOLVE → 清空合法响应 → 终局检查 → DISPATCH

DISPATCH：
    已终局 → BATTLE_END
    有尚未结完的响应 → RESPONSE_DRAIN → DISPATCH
    有可执行战机票据 → WINDOW_PRE(OPPORTUNITY)
    否则有普通就绪单位 → WINDOW_PRE(NORMAL)
    否则 → PUBLIC_TICK → 响应、资格登记、终局检查 → DISPATCH

实际进入窗口：
    普通才处理NORMAL_PRE状态，并检查存活
    W += 1；普通另R += 1
    建立window_id与本窗记录
    战机才兑现一张票据并进入安全锁
    处理该类型的开始事件 → DECISION

DECISION：
    END → WINDOW_CLOSE
    指令核验失败 → 不改状态，回DECISION
    换法成功 → 占该格与本窗换法机会，回DECISION
    主动作成功 → ACTION_COMMIT → EFFECT_RESOLVE／RESPONSE_DRAIN
               → ACTION_CLOSE
               → 普通：WINDOW_CLOSE；战机：回DECISION

WINDOW_CLOSE → 对应结束事件／响应 → 清除活动窗口 → DISPATCH
```

任何原子结算组产生终局时，停止还未执行的技能后句、响应和机会，进入BATTLE_END。不能执行终局后的补血、待发战机或额外攻击来撤销结果。导致终局的已提交组仍须完整记账；当前施法记录为“因终局中止后续”，不能漏掉已支付或已造成的部分，但不再发放无用途的新战机资格。

### 4.3 战机登记与优先级

Z满不直接调用“开始回合”。在当前结算组、响应队列与整次动作收尾的安全点检查资格，形成票据；票据最多一张。玩家或AI当前整个窗口未关闭前，不启动别人的战机，也不在当前施法两句之间插入自己的战机。

票据登记顺序固定为：登记公共刻、资格登记批次、该批次快照中的有效S降序、本场固定单位顺序。一次同时结算内产生的资格共享批次，不靠逐目标遍历制造先后。

DISPATCH优先取合法战机票据，再取普通就绪机会。普通同批就绪按有效S与固定顺序；票据已经登记后不因动画先播谁而改变排序。

没有合法队列和机会才推进公共刻。不能为等某个偏好的角色而跳过已就绪者。

### 4.4 自动满条、可拒绝施展、不可拆招

战机到调度点自动进入，不要求玩家每次点“激活”；玩家进入后仍决定用什么，可以空窗结束。空窗也消耗本次机会并进入安全锁，不退回满条。

本轮不提供手动囤多个战机、无限延迟兑换或对敌方施法中的实时插入。多人都有待执行资格时按同一队列处理，不能一律玩家先行。

## 5. 战机获取、安全锁与试验参数

### 5.1 获取渠道

**共识：**基础每公共刻增加，战斗中的有意义成果可使其提前蓄满。

**首版默认：**先启用自然增长和自己的普通主动作造成实际敌方气血损失两类。个人护体实际吸收的奖励作为显式关闭的对照渠道，只有补齐来源与守恒测试才可打开；防护打法仍有相同自然增长。暂不奖励使用次数、点击数、无效加盾、溢出治疗、自己伤害自己，或仅仅被敌人打掉气血。

自然增长为所有参与战机机制的存活主战单位提供底线，不把“能制造最多伤害”设为唯一获得战机的门票。灵宠本次内核默认不开启战机资格；将来开启须显式设定，不继承主角Z。

### 5.2 普通行动进度与自然战机

```text
普通行动增长 = max(5, round_integer_sqrt(S) + 神速层数 + 已明确行动增长修正)
A_new = min(100, A_old + 普通行动增长)

Z_new = min(Zmax, Z_old + passive_gain)
```

Z的自然增长首版不再乘S。速度通过更多普通行动可能增加行为收益，但不会额外再乘一次战机自然速度。修改神速时仍只改普通行动增长，不改S排序和战机自然值。

### 5.3 行为奖励的参考算法〔试验参数〕

开战快照保存正整数参考尺度`combat_scale_ref`。本轮小尺度训练统一取300，双方共用；它是场景的数值单位，不是被攻击目标或自身的当前气血，也不是独立可加点属性。镜像难度只调整Hmax时，不随之改这个参考值，避免气血变多反而暗中降低充能效率；全套数值尺度变更时才同步调整参考值。

按一个根动作汇总某单位的合格实际伤害L和合格护体吸收B，在该动作收尾时统一计算：

```text
z_damage = floor(damage_weight * L / combat_scale_ref)
z_guard  = floor(guard_weight  * B / combat_scale_ref)
z_event  = min(root_gain_cap, z_damage + z_guard)
Z = min(Zmax, Z + z_event)
```

L不含护体吸收、过量伤害、自伤和气血支付。B渠道默认关闭；启用后仅包括本单位普通主动作产生的护体实际吸收，不包括战机产物和法宝赠盾。多人、多段的合格量在同一根动作内先汇总，再限额／取整，不每段独立送一次奖励。

**防护奖励是扩展接口，不是首版阻塞项。**本轮`guard_weight=0`，不需要为了一个未启用渠道先做复杂来源账。将来启用前须定义混合盾来源的合格吸收分配、溢出、Hmax截断和计数上限，并保持同名护体一个总池和共同上限；不能把自动法宝赠盾、战机赠盾的收益默认冒认为普通主动防护，也不能重新引入不同批次独立到期。定义与测试未齐全时保持关闭。

本轮先不从周期侵袭、蚀骨、回春或混合来源状态池计算战机奖励；这样避免为战机随意重建同名Buff批次。如果以后开放，必须先定义真实来源与根动作归属。

### 5.4 不自我连锁的规则

- 战机根动作及其延迟、派生事件不为任一方提供行为战机奖励；原始窗口类型写在事件因果信息中，不能因延迟到普通阶段就洗掉。
- 法宝自动功效、灵宠行为不默认给主角攒行为战机；主人和灵宠分开。
- 进入战机时Z清零，不保存本次充满的溢出，不堆多张票据。
- 战机结束后，至少完成一次自己的普通回合才能再次兑换战机。普通回合空过也可解除锁；其他人的普通回合不能解除。
- 锁定期间允许自然及合格的非战机行为积累，最多到Zmax；满了显示“等待下次普通回合结束”，不立即插入资格。解锁后在安全点登记一次票据，登记时点采用此时，不追溯占据锁定期间的旧队列位置。
- 战机窗口内没有公共刻，所以不会凭动画、思考或技能数量自然充能。

这些规则只阻止无普通节奏的连续兑换，不承诺任何策略都不会吃亏。战机不会自动替玩家施法，也不会替他免除自选动作的明确费用。

### 5.5 第一组测量参数，不是定稿

| 参数 | 起始值 | 校准问题 |
|---|---:|---|
| Zmax | 100 | 统一进度展示 |
| passive_gain | 2／公共刻 | 无行为奖励约50刻获得第一次资格 |
| damage_weight | 60 | 普通实际输出能提前多少 |
| guard_weight | 0 | 首版关闭；补齐来源定义后可用30作对照，不默认启用 |
| root_gain_cap | 12 | 多段／群体不刷出无界奖励 |
| 初始Z | 0 | 不自动每战送一次完整爆发 |
| 已登记资格上限 | 1 | 防止囤积连续窗口 |
| 两次兑换之间自己的普通回合数 | 至少1 | 给普通节奏保留位置 |

例：参考气血300、每10刻一次普通行动、每次合格攻击实际损失30。自然增长每10刻20点，攻击提供6点。无其他干预时，前三次普通动作收尾分别为26、52、78点；第40刻自然增长到98，再攻击时达到100，在普通窗口结束后登记并调度战机。这个例子只是算术，不证明4次普通出手一定合适所有遭遇。

同一事件造成5点合格损失，拆成2＋3或一次5都按汇总后计算1点奖励，不能分别取整。数值尺度等比变化时，损失与参考尺度同步变化，不能使千血版天然更快攒战机。

## 6. 自动法宝、灵宠与行为归属

### 6.1 每个事件至少区分四种身份

| 字段 | 意义 |
|---|---|
| `owner_id` | 这件法宝／单位归谁拥有，用于归属与展示 |
| `actor_id` | 谁实际执行该行为；可以是法宝实例而不是一个角色 |
| `source_kind / source_id` | 主动功法、基础攻击、法宝自动ARTIFACT_AUTO、主动催动ARTIFACT_CATALYST、灵宠技能、周期状态等来源 |
| `resource_owner_id` | 若有费用由谁支付；免费自动功效为空，不默认填主人 |

再记录目标、根动作、父事件、原始窗口类型、是否为主动施法、是否允许提供战机。手动／AI只决定控制方，不能改变这些规则身份。

### 6.2 主角、自动法宝、灵宠的边界

| 项目 | 主角主动法 | 自动法宝 | 灵宠主动行为 |

| 是否主角主动施法 | 是，AI代操作也一样 | 否 | 否，是灵宠自己的行为 |

不设“自动行为忽略所有减益”的规则。主角开启自动战斗，仍承担主角施法的全部条件和费用；灵宠有自己的减益，也不能免除。法宝可以由专门“法宝威力”来源提高，但不隐式套用主人所有个人攻击增益。

### 6.3 自动功效与独立主动《催》〔2026-10-05作者纠正，替换1.0误定义〕

**法宝保留两条独立能力：自动功效与《催》。需要修复的是自动功效还能被手动调用，并非删除《催》。**此前“全部法宝只自动、移除催动”的要求是助手对作者意图的误解，在本版本撤销；其他双窗口、归属与时序规则不因此回退。

- 自动功效：只接受已声明的事件。普通开场绑定`NORMAL_OPENED`，入场绑定`BATTLE_ENTRY`，条件保护绑定真实敌对受伤。自动图标仅供查看，不提交指令，不扣主人即时H/E、不消费主人锋锐、不占主动入口、不改变《催》的CD或本窗已用状态。
- 主动《催》：数据必须有独立的`active`成品，不使用`auto`数组作为默认回退。效果可以与自动效果属于同一类型（如都伤害或护体），但执行哪条效果由入口决定，不能因为同类效果就断言重复触发。无`active`的法宝不生成《催》候选。
- 普通回合：《催》是一次主动作，与功法、基础挥剑择一；不占四个功法格。战机回合：每个《催》入口至多一次，不能点击重放；不同《催》与已就绪功法可以依次使用。
- 《催》使用独立`active_ready_window`与`active_used`。基础CD=N≥1，成功使用登记`W+CD`；普通与战机均按W推进，自动触发次数不推进它。每窗清理已用标记，不清理恢复窗口。
- 《催》属于持有者主动施法，来源为`ARTIFACT_CATALYST`；实际支付者为持有者，适用撕裂、逆气、凝神，H必须大于气血支付。含本人直接攻击时，适用并消耗本人锋锐；这不把自动攻击变成本人攻击。
- 自动计次与主动回转互不锁定、互不重置。一次普通开场自动攻击之后，玩家选择《催》是合法的另一项能力；只有再次手动调用自动那条才是重复触发。使用《催》不重领入场护体、不重置低血首次标记，也不重放普通开场攻击。
- 战前“自动”开关只控制自动部分，不停用合法《催》；卸下整个法宝另按装配规则处理。
- 该主动根动作正常遵守战机奖励口径：普通回合中符合条件的实际伤害按一次根动作汇总，战机中不返还行为战机。它产生的自动后代仍不贡献主动伤害奖励。

恢复六件已发布法宝的主动作用。灵铁剑与金缕衣保留作者原主动给值；其余四件保留2.2.2的主动效果类型，以十倍旧训练尺度的直接量／费用除十作为**本次小尺度工作值**，不是全体系已平衡。自动给量与F不变，不把主动量补到自动上。

### 6.4 简单安全保护，不要求自动系统永远最优

无合法目标、来源已经失效、必要条件不满足、灵宠无法合法支付时，不发动相应行为，记录原因；灵宠可按简单预设选替代或结束。不得让自动功效直接操作主人H/E来“代付”；《催》经正常原子支付流程由主人主动承担费用。

首版不引入把法宝攻击后果默认反伤到主人的内容，也不实现全局任意反击链。将来引入反伤、反击或攻击触发敌方增益时，必须一起定义作用来源和可预见的控制方式，不能一边说自动安全，一边加入无提示的强制自杀链。

允许战前关闭可选自动项；首版不要求每次自动发动弹窗确认。设置改变仅在允许的配置边界生效，不能在伤害组中途开关规避既已提交效果。

### 6.5 低血护身的唯一语义

训练样本默认：**某次合法敌对伤害组提交后，实际气血损失大于0；持有者仍存活且当时低于40%Hmax；本场尚未登记过该法宝触发，则登记一次后置护体。**

只打掉护体、支付气血、自伤不触发。公共周期组只有敌对伤害请求且净气血下降时可触发，使用该组单独的净损失事件，不伪造逐来源实际损失。该口径属于本次明确的模板默认。

致死伤害不救回；第一击后生成的护体能挡第二击，不能倒改第一击。两个法宝同时满足阈值时都以该事件快照判资格，随后按队列顺序处理；不是第二件再用第一件触发后的状态重新猜资格。

## 7. 一次施法的完整协议

### 7.1 玩家提交前与提交后

**提交前：**可以查看、换目标、取消。确认时再检查阶段、行动权、窗口额度、槽位、CD／同源等待、整门条件、目标与全部开始Cost。

**提交节点：**开始Cost原子扣除，登记主动作／槽位已用、恢复窗口、同源等待和`cast_id`。后面条件未命中、伤害被挡、取整为0或恢复溢出，都不回滚这个节点。

```text
气血支付必须 H > hp_cost；灵气支付必须 E >= qi_cost
qi_cost = max(0, 战前解析的基础灵气Cost + 逆气 - 凝神)
hp_cost = max(0, 声明的基础气血Cost + 撕裂)
```

费用只对一次完整主动施法收一次，多句／多目标／多段不重复收费。基础挥剑是基础攻击，不默认算主动施法；攻击来源与支付类型分开。

### 7.2 整门前提、句内条件与实际消耗

“目标有至少9层印记才能开始”在提交前检查；“第二句只在目标有印记时执行”在第二句声明的读取节点检查。

读取不消耗。需要用印记作为燃料时，显示独立消耗句，并记录实际消耗；开始核验可以预查足量，但不能又先扣一次。

首版普通内容以共享开始Cost为主。明确分步Cost时，该节点先原子核验；失败不部分扣款，默认中止余下施法；已支付和已发生的效果保留。不能根据本次成功执行几句临时减少CD。

### 7.3 施法内的原子结算组

- 一次独立攻击组：同一出手的全部合法目标，在共同快照上计算并共同提交；再检查存亡与响应。
- 连续两次攻击：两个组；第一组后允许规定的受伤后自动响应，第二组读取更新后的战斗状态。
- 一次同类状态施加／治疗组：对该组目标按声明范围共同处理；源方共享状态不按遍历顺序重复消费。
- 一个公共刻组：全部存活单位基于刻开始快照计算，自然回气、条增长、周期伤害／恢复和规定衰减一起提交。

组内禁止插入另一个窗口或玩家临时指令。组间可以按固定节点清空自动响应；“不能打断整次施法”不等于施法所有句同时发生。

### 7.4 公共刻净收支

对每名单位，按刻开始H0、回春Lh、侵袭Ld计算：

```text
H_after = clamp(H0 + Lh - Ld, 0, Hmax)
回春下一层数 = max(0, Lh - 1)
侵袭下一层数 = floor(Ld / 2)
```

同组所有单位提交完再判存亡。H0=5、Lh=5、Ld=8时结果为2；不能先死亡再拒绝本来同时发生的恢复。

新施加的周期状态从下一公共刻开始，不在产生它的当前公共更新里递归跳一次。公共刻内没有窗口前蚀骨，也没有“每出现一个角色就让回春多跳”。

### 7.5 死亡与终局

普通伤害组与公共周期组分别在组提交后检查。角色H=0立即不可继续行动；同组双方主战角色倒下判平局，其余按明确战斗目标判断。本次1对1训练以主战角色倒下判胜负。

判定终局后，封存尚未执行效果为取消，取消待执行战机和自动触发，不复活、不补结无意义的最后一刀。支付记录和已提交损失保留。未来死亡触发、复活、保护主目标等必须专门定义，本轮不暗设。

### 7.6 反伤、替代和响应不能混成一个钩子

伤害提交前的护体吸收属于计算／防护规则；受伤后生成护体是后置响应；战机满产生的是待调度资格。三者不能都注册为一个模糊的`on_hit`。

首版只有已经明确的防护和后置模板，没有玩家手动连锁响应，也没有“任意效果都能插入支付过程”。新增时点是底层规则变更，不是普通内容参数。

## 8. 事件字典、自动队列与结果证据

### 8.1 最小事件字典

| 事件ID | 产生节点 | 内容可订阅的事实 | 不表示什么 |
|---|---|---|---|
| `BATTLE_ENTRY` | 全部初态建立完毕 | 本场入场 | 读档不是再次入场 |
| `PUBLIC_TICK_COMMITTED` | 本公共刻整体提交后 | t、各单位请求与净变化 | 不是某人主动施法 |
| `NORMAL_PRE` | 普通机会将实际进入前 | 普通窗口前检查 | 不在战机时产生 |
| `WINDOW_OPENED` | 实际W增加后 | 窗口ID与类型 | 不自动重复所有旧“回合开始”Buff |
| `NORMAL_OPENED` | 普通W、R增加后 | 普通周期开始 | 不在战机时产生 |
| `OPPORTUNITY_OPENED` | 战机资格兑现后 | 消耗资格、当前Z与A | 不补气、不全清CD |
| `SPELL_COMMITTED` | 开始支付／占用提交后 | 整次Cost、法门与恢复窗口 | 不是每个伤害段 |
| `EFFECT_GROUP_COMMITTED` | 一个原子效果组提交后 | 请求、实际、防护、目标与结果 | 不是新行动权 |
| `HP_DAMAGE_TAKEN` | 独立伤害组实际扣血后 | 非支付、非溢出的实际伤害 | 完全被护体吸收不产生正量事件 |
| `PERIODIC_NET_HP_LOSS` | 周期组整体提交后 | 有敌对伤害且净气血降低 | 不虚构每个周期来源的独立实际伤害 |
| `STATUS_CHANGED` | 状态操作提交后 | 实际新增／移除、前后层数 | 读取状态不触发 |
| `SPELL_FINISHED` | 整门法全部合法后句和响应完成／明确中止后 | 成功开始与最终完成状态、已提交的结果 | 中止不等于从未支付 |
| `ROOT_ACTION_CLOSED` | 根动作及规定响应全部排空后 | 统一的行为战机统计批次 | 子事件不得重复登记同一奖励 |
| `OPPORTUNITY_QUALIFIED` | 安全点发现Z已满且可登记 | 资格票据 | 不直接重入调度器 |
| `NORMAL_CLOSED` | 普通回合收尾 | 本普通周期结束 | 不是每次法宝触发 |
| `OPPORTUNITY_CLOSED` | 战机收尾 | 爆发结束，A不清零 | 不触发普通结束衰减 |
| `BATTLE_FINISHED` | 最终存亡／中止／观察判定 | 本场终态 | 不能由动画回调再次写入 |

正式事件字典只允许这些明确入口及已有必要的支付／跳过诊断事件。**存在事件不等于所有内容都可订阅：**首版法宝自动模板仅开放`BATTLE_ENTRY`、`NORMAL_OPENED`、`HP_DAMAGE_TAKEN`和`PERIODIC_NET_HP_LOSS`；普通周期Buff使用第9.4节的固定内部节点，战机奖励使用固定的根动作收尾节点。`SPELL_COMMITTED`等其余记录先用于执行、统计和调试，不因此开放任意“施法时再施法”。新增订阅节点须说明相对阶段、快照和权限；未知字符串不能当“先兼容再说”。

### 8.2 事件结构

每条事实事件至少记录：

```text
规则／内容版本，battle_id，event_id，parent_event_id，root_action_id
当前phase，t，window_id，window_kind，owner.W，owner.R
owner_id，actor_id，source_kind，source_id，resource_owner_id
cast_id，sentence_id，execution_id，effect_group_id，target_ids
原始根窗口类型，触发来源类型，战机奖励资格标签
请求值，已提交实际值／净值，相关状态前后值，跳过／取消／截断原因
```

不存在的上下文字段明确为空：例如实际进入前的事件没有已成立的window_id，只记录候选窗口类型，不借用上一个窗口ID，也不提前增加W。法宝等非角色执行者没有自己的H/W时，不伪造角色记录，只保留所有者和来源信息。

事件是已发生事实，不能被后续脚本改写成“其实还没扣”。表达式读取已经封存的前句结果；UI只读这些记录，不从动画猜测伤害是否已经发生。

### 8.3 自动响应队列〔首版执行默认〕

发生一个可订阅事件后，按**事件发生时快照**收集满足条件的触发实例。记录每项触发依据，预留一次性额度，形成任务，不直接递归调用整门法或新窗口。

同一响应边界的顺序为：事件序号、明确优先级、来源在本场的装备／单位顺序、稳定触发实例ID。优先级只是同类后置任务顺序，不能让它跨到支付前或其他阶段。

执行任务时再核验来源／目标是否仍合法、是否存活等执行条件。阈值是否曾满足依据原事件，不因为前一任务改变气血而重判原事件。来源死亡则取消；已预留本场一次额度默认不返还，记录取消原因，避免反复入队。

任务产生的新后置任务追加到当前队列尾部，不递归抢占已有同级任务。队列排空后返回原施法下一组；不得开启另一个主角决策窗口。对于更深队列，当前层与下一层的顺序同样保留，不使用语言调用栈决定结果。

### 8.4 触发次数必须带作用域

合法示例：每场一次；每个自己的普通回合一次；每个自己的出手窗口一次；每个根动作一次；每个独立攻击组一次。

不得只写“每回合一次”而没有时钟，也不得用每渲染帧重新检查条件代替事件。

每项可重复触发都须有重置点。持续监听和相互触发的新内容在规则图上必须有可证明的有限边界。首版禁止自动反击相互反击、产战机链自我充能、未声明的费用回滚或重置CD。

程序安全上限只用于捕获错误：报错、中止并保存队列和因果链，不悄悄截掉后续当作正常结果。

### 8.5 原子性与玩家可见性

开始费用核验和扣除是一个原子节点；多目标一次攻击是一个原子组；整个公共刻也是一个原子组。组内部不处理输入或外部AI结果。表现可以分段播，但始终对应提交时点。

战机满条动画可以先提示“战机就绪”，但不能在当前动作尚未收尾时开放战机按钮。当前普通回合与所有任务结束前只显示待执行状态。

## 9. 规则句、Buff与新时序的对应

### 9.1 标准句数继续计实际基础作用

| 内容 | N计数 |
|---|---:|
| 造成一次伤害，伤害量读取人物参数 | 1 |
| 有印记才造成伤害 | 1；条件不另计 |
| 造成伤害，再按该次实际损失施加侵袭 | 2 |
| 消耗印记，再按消耗量造成伤害 | 2 |
| 一次同时攻击多个合法目标 | 1；人数、范围另定价 |
| 对同一目标独立攻击两次 | 2 |
| 将“伤害→施加”重复两遍 | 4，超出首版三句上限，拒绝发布 |

N以保存方案展开结构为准，不按这次实际成功几句变化。读取、目标判断、表达式算术和伤害内部防护不是独立功能句。

当前蓝本一／二／三阶容量分别最多1／2／3句。高阶蓝本只使用一句时CD为1。普通数值提高不变N；分化选择增加独立执行时改变N和CD，保留旧方案。

不允许复合名称、无界监听、任意召唤把多项作用免费包装成一句。已有基础Buff是审核过的原语，其按公共定义运行不按每次跳数增加N。

### 9.2 三层数据与表达式

**成品层**保存：蓝本ID、版本、同源ID、主要系列ID、结构容量、整门前提、开始费用、有序句列表、展开N／CD、承载与已保存的研究方案。

**句层**保存：稳定ID、执行组、目标、前提、基础操作、数值来源、参数与成长绑定、读取节点、取整、分步费用及结果类型。

**公共层**保存：基础操作、伤害类别、Buff算法、生命周期、相互作用与事件节点。

首版允许：造成指定性质伤害、治疗、恢复／扣减指定灵气、施加一种审核状态、消耗／移除一种状态，以及已登记的“清除减益类别”操作。类别清除计一个已审基础操作，不等于任何新命名的复合Buff都可免于展开。完整清除使用`mode=ALL`，不用99999伪装无穷大。

不开放任意写H、任意改W、循环脚本或动态改变句数。新操作必须有输入、结果、合法性和事件定义。

### 9.3 结果引用要有确定类型

结果键为`cast_id / sentence_id / execution_id / target_id / result_field`。

伤害区分基础请求、修正后请求、实际护体吸收、实际气血损失；治疗区分请求、实际恢复、溢出；状态区分请求、实际新增／移除、已有总层数。不能用一个未经类型检查的`actual`混指这些概念。

只允许读已经完成的前句，不读未来、不自引用、不成环。多目标默认逐目标对应，自身后句读取敌方主目标结果须显式标记，不由代码“找不到自己就猜主目标”。聚合需显式目标集合与方式，空集合按缺失处理。

执行为0不等于缺失。条件跳过、目标失效或未执行的前句，后句默认跳过并说明；只有成品明确配置替代值才使用替代。后句引用不受中途法宝事件影响。

### 9.4 11项基础Buff绑定矩阵

本表保留既有公共算法，明确其与普通／战机窗口的关系。自然生命周期仍未确认的项目，本轮测试保持层数至清除或本场结束；不擅自新增倒计时。

| Buff | 公共作用 | 绑定时点／归属 | 战机窗口的处理 |
|---|---|---|---|
| 护体 | 每层吸收1直接伤害，总池≤Hmax；按实际吸收消耗 | 伤害组计算；目标持有者的防护 | 正常防护，不因进入战机额外减少 |
| 锋锐 | 每目标直伤加`min(层数,该目标基础直伤)`；同一次出手结束减1 | 持有者自己的直接攻击；多目标共同开始层数 | 每次实际个人攻击正常结算；自动法宝不借主人锋锐，主动《催》的本人攻击按其规则适用 |
| 神速 | 每层使普通行动进度每刻增长+1，不改S排序 | PUBLIC_TICK | 战机无公共刻，不另加A或Z |
| 凝神 | 每层使整次主动施法灵气费用−1，最低0 | SPELL_COMMITTED的费用节点 | 自选施法照常适用，不减少CD |
| 鲸吞 | 每层使自然回气+1／公共刻 | PUBLIC_TICK | 不在战机入口免费补气 |
| 回春 | 每刻按层数恢复，随后减1 | PUBLIC_TICK共同提交 | 不因额外窗口多跳 |
| 侵袭 | 每刻按层数造成效果伤害，随后向下减半 | PUBLIC_TICK共同提交 | 不因额外窗口多跳；战机所生层数也不会自行返Z |
| 蚀骨 | 当前H×层数1%，全部层数合算后按公共整数规则处理 | **NORMAL_PRE** | 本次改为仅普通窗口前触发；战机前不额外触发 |
| 撕裂 | 每层使一次主动施法开始气血Cost+1；正常周期结束层数减半 | SPELL_COMMITTED；**NORMAL_CLOSED** | 战机中自选每门施法照付；战机结束不额外减半 |
| 逆气 | 每层使整次主动施法灵气Cost+1 | SPELL_COMMITTED | 照常适用，不改CD |
| 滞气 | 每层使自然回气−1，最终最低1／刻 | PUBLIC_TICK | 不关闭法宝，不改变F额度 |

蚀骨和撕裂的周期重绑是本次为“额外窗口不强迫额外受损或白送衰减”作出的**首版执行默认**，不是声称旧版本本来如此。凡文案写“自己的回合”要同步改成“自己的普通回合”，否则玩家会误读。

护体不挡效果伤害，也不代付气血。神速、凝神、鲸吞、蚀骨、逆气、滞气默认保持层数；相反费用或回气修正先合计后处理。印记只保存标记和层数，不自行伤害、回复或触发额外窗口。

属性下调导致护体超过Hmax时截断，Hmax上升不补盾；溢出不保存、不转其他资源。不复活旧名与旧基础免伤／格挡规则。

### 9.5 一次完整时序算例

主角在普通W=3施放N=2、CD=2的“伤害→按实际伤害施加侵袭”。提交时登记到W=5恢复。第一句后目标低血护体可以按响应队列触发，但不改写第一句实际损失。第二句据此产生侵袭。

动作收尾使主角战机充满：先登记资格，完成普通结束，再调度进入战机W=4。刚才的双句法仍不能用；其他CD已到的技能可用。战机不额外跳侵袭／回春、不跳蚀骨、不重复普通窗口法宝、不自然回气。

战机中施法仍支付自己的撕裂／逆气费用，W不逐招增长；结束保留普通行动进度。之后取得普通W=5时，那门双句法恢复。

## 10. 人物成长、系列熟练与本法熟练

### 10.1 不做积累流程，但必须计算不同施法者的差异

当前Demo输入可以预设人物能力与熟练等级，不要求挂机、获得经验、升级动画或开放任意公式编辑。使用同一成品，由不同能力和熟练的角色施展，必须真正产生不同结果，而不是替换成另一张写死更大伤害的卡。

沿用控御、节用、凝练、分化。人物额外增加气血、M、Q、速度，不默认同时提高所有单次效果。效量成长先由凝练进入，不新增一个和凝练重复加点的“法术攻击”属性。

### 10.2 四种来源分开

| 来源 | 字段职责 | 不与什么混同 |
|---|---|---|
| 功法模板 | 基础值B、人物转化系数、结构、条件、目标 | 不是当前人物最终伤害 |
| 人物施法效能P | 从凝练派生；首版直接采用一个非负整数效能输入 | 不是气血、速度、当前剩余灵气的无条件倍数 |
| 系列熟练 | 以`proficiency_group_id`查该人物系列熟练加成 | 不作为同源装配锁 |
| 本法熟练 | 以`source_family_id`查本门法熟练加成 | 不因保存单句／双句版本重新归零 |

首版每门法只使用一个主要系列熟练度；多标签不各送一份完整加成。人物可以同时擅长多个系列，不形成互斥职业。沿用现有`source_family_id`表示这门法的同源身份，同时作为本法熟练的索引；新增`proficiency_group_id`表示更广的系列，不创建另一套可能与同源身份失配的本法ID。

### 10.3 首版直接效量公式〔执行默认，数值待测〕

```text
base_effect = B + (a_num / a_den) × P
mastery_factor = (10000 + series_bonus_bp + technique_bonus_bp) / 10000
requested_effect = round_declared(base_effect × mastery_factor)
```

使用整数分子分母计算，整个效量节点最后取整一次；不先把系数取成整数，不使用隐藏小数余量。B、P非负，分母为正；倍率有效范围有数据校验。

默认熟练加成相加，不把人物、系列、本法、每句结果全部层层连乘。伤害还要经过当次适用的个人增益、目标修正和护体，不能把`requested_effect`称作一定扣除的气血。

旧`mastery.potency=100`是旧测试字段，不能不作单位说明就转成新P=100。新快照必须显式写出P、系列等级与本法等级；或有明确版本迁移映射。

### 10.4 首组熟练对照表〔试验参数〕

| 测试等级 | 系列加成 | 本法加成 |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 500基点（5%） | 1000基点（10%） |
| 2 | 1000基点（10%） | 2000基点（20%） |

原始使用次数不是倍率；正式经验曲线、成长来源与上限后置。正常训练默认所有对照角色先使用相同等级0，另提供成组的“人物更强／系列熟悉／本法精熟”测试快照，避免同一次比较偷偷改变多项。

### 10.5 绑定与反复放大的边界

根效量参数可以绑定P和熟练。派生句读取前句已结算结果时，默认不再套同一份人物与熟练加成。系数本身的本法研究可以另行提高，但必须有独立绑定与定价。

目标数、执行次数、消耗、条件门槛、触发次数、持续时间、战机收益、CD不因为“效量变强”一起乘大。治疗仍是治疗，不因凝练变成另一种操作。

普通能力成长不自动提高固定使用费用、结构N或使旧保存方案失效。主动选择更大投入、更大范围或更多独立执行，是另外的结构方案，重新核验费用与承载。

同一根句的施法者P和熟练默认在施法提交时锁定。对目标的当前气血、状态等，按该句声明的`CAST_START`或`GROUP_START`取值；没有声明不得自行在两者之间切换。Buff与防护仍按真实组时点处理。

### 10.6 用于验证的三种方案，不是最终内容报价

同一法门基础值10、系数1。测试人物P=20、熟练加成0，直接请求为30；P=40且系列10%／本法20%时请求为65。

| 方案 | 规则结构 | N／CD | 试验基础费用 |
|---|---|---:|---:|
| 单句 | 直接伤害`(10+P)×熟练因子` | 1／1 | 10 |
| 双句 | 上述伤害；按实际气血损失20%向下取整施加侵袭 | 2／2 | 18 |
| 三句 | 上述两句；按实际新增侵袭层数×2施加自身护体 | 3／3 | 24 |

无防护、无上限和过量伤害时，强测试快照得到65伤害、13侵袭、26护体。后两句不再次乘1.3。同源方案不能同时占多格绕CD。

这些是语义、成长与时序的对照夹具，不宣称已形成公平报价。主流程的首批成品须逐一重新定价并绑定版本。

## 11. 数值尺度、内容定标与战斗节奏

### 11.1 小尺度训练基线

用户反馈当前几千血与高技能数值阅读负担偏大。基线代码的C01为Hmax=3000、M=1600、Q=70、S=121，沿用此前十倍资源测试尺度，不是已确认最终数值。[S1][S4]

本次采用一组小尺度对照起点：

| 人物ID | Hmax | M | Q／刻 | S | 初始P | 默认熟练 |
|---|---:|---:|---:|---:|---:|---|
| C01 均衡 | 300 | 160 | 7 | 121 | 20 | 系列／本法均0 |
| C02 储备 | 360 | 200 | 6 | 100 | 20 | 同上 |
| C03 周转 | 270 | 140 | 10 | 121 | 20 | 同上 |
| C04 疾行 | 270 | 120 | 6 | 196 | 20 | 同上 |

这是试验输入，不宣称四个人物等强或有相等培养成本。C02旧Q=55不能整数等比缩成5.5，此处6是明确重定值，不说成无损缩放。最终值须看新一招普通回合和战机下的真实对局。

不只缩界面、后台继续大数；显示与运行使用同一整数值。也不为了小数值引入未经采用的隐形小数层数。

### 11.2 哪些不能一起除十

S、A上限、Z上限、t、W、R、CD、N、目标数量、执行次数、概率、阈值百分比不按资源单位缩放。

Buff逐项重定施加量，不能机械缩层数。回春35层无干扰总请求630；4层只请求10，既不是63，持续过程也不同。侵袭层数、锋锐每击消层、凝神／逆气每层费用、蚀骨百分比等都有各自整数门槛。

法宝F与基础Q同属装配关系；Q缩小后F必须有显式新标定，否则旧合法配装会被误判非法。基础法宝旧给值保留历史，新版内容分别标记自动与《催》，不能混用主动收益补贴自动效果。

### 11.3 首轮内容定标按三个维度分开

**节奏：**普通一招有无取舍，第一场关键战能否至少出现一次有意义的战机，战机后是否仍有对方回应；不能把长血条当策略深度。

**资源：**同样一组本领能否适度留气、回气或集中投入；不希望所有正常窗口都被迫空过，也不希望所有窗口永远轻松打满。战机不免费补气，因此满Z但无气时的准备是否充分，是需要观察的选择。

**结构：**单句、双句、三句与同源版本各有使用场景。CD=N不是强度证明：三门CD=3的三句法依次轮换，仍可能每个普通回合释放三项作用，需要同时检查费用、效量、槽位与敌情。

不按“基础作用份数／CD”完成全部平衡。不把一个短战只施一次的高威力法，用战斗结束后永远不会支付的长等待抵价。

### 11.4 必须承认的新收益与损失

普通供气、恢复、印记准备现在占一个主动作，比旧的每窗全施更贵；复合法获得集中多个功能的一次行动价值。独立《催》保留净化、治疗、进攻等主动应对；普通回合须与功法竞争一次主动作，不把新增的主动选项误作每回合额外免费行动。

旧三窗四门全施最多12次；新三次普通出手加一次四门战机最多7门次。新机制可能更有起伏，但不保证更快；气血、效果与恢复都需要新定标。

已有成长公式并不等于已有成长乐趣。要检查同一法门在更强快照下有清楚回报，旧低耗方案能保留，新结构没有把升级变成强制变慢。

## 12. 玩家信息、演出与操作

### 12.1 信息分层

普通战斗主视图显示：当前行动者与窗口类型、H/E、普通行动条A、战机条Z及就绪／锁定状态、四格费用与CD可用性、重要状态。不能只用颜色区别普通与战机，应有文字或图标标识。

普通窗口明确提示“一次主动施展”；完成后进入收尾。战机窗口有明显进入提示，允许逐门选择并在整次施法后观察；不能把整个战机自动提交成一串不可撤销的玩家指令。

基础说明使用玩家语言；详细面板再显示N、W、R、来源、引用字段和公式拆解。不要把整套事件协议堆在屏幕上。

### 12.2 冷却和换法文案

统一写“CD 1：下次自己的出手机会可用（含战机）”。等待时按真实W显示“还差几个自己的出手机会”，附实际最早恢复编号供调试，不写不确定的“下回合肯定转好”。

换法预览显示：本窗不能使用、新法所继承格子和同源等待中的较晚者。法门自身CD、该格当前剩余等待、当窗已操作是三种不同状态。

### 12.3 公式与战机收益预览

技能说明由真实模板与当前人物输入解析，不再手写一组和执行器平行的伤害数字。根效量显示基础、人物贡献、熟练加成；派生句明确“按实际气血损失”等条件。

普通行为的战机预估标明条件与上限；真正增量在根动作收尾显示，完全被护体吸收、目标倒下或免除不合法结果会改变预估。不要把预演的满Z当真实资格。

战机自然增长、输出奖励、安全锁下暂存和溢出应能在展开记录中解释，普通主界面不必逐条打断提示。

### 12.4 动画和输入不推进规则

可以有战机入场强调、连续施展镜头和更集中的反馈，但不得依现实计时给玩家限时操作。倍速／跳过动画只缩短播放，不多发事件、不回气、不推进CD、不改变AI预算。

组已提交而动画未播完时不开放下一个玩家指令。后台AI回包必须匹配battle_id、window_id、阶段和观察版本；暂停、重试、中止、实际新事件可使旧计划失效。

法宝自动图标只显示自动来源与效果；另设明确标注《催》的主动按钮。点击自动图标不施法，点击《催》预览独立作用、费用与CD，再确认目标。首版暂无灵宠主流程，不展示不能使用的空宠物系统。

## 13. AI修改与评估方式

### 13.1 保持三档职责，不靠作弊

简单按合法固定顺序，不发非法指令；普通理解当前有效结果与有限后续；困难比较合法组合和多种可能回应。镜像主流程数值与AI联合变化不改，纯算法对照另锁面板和配装。

自动战斗与玩家操作使用相同行为归属、阶段、费用、战机来源和CD。AI只读被允许的公开状态，不读玩家悬停、下一次点击或未来随机结果。

### 13.2 普通窗口和战机窗口必须采用不同搜索约束

普通窗口候选为“最多一次合法准备换法＋一个主动作”或直接结束，不能继续执行旧的一窗多法序列。准备型技能的收益可以来自下一普通／战机机会，但不能在模拟里让它同窗接一招实际不允许的攻击。

战机窗口搜索剩余合法入口的有限排列。首版战机动作上界来自四功法格、最多两个独立《催》入口、一次基础挥剑以及一次准备换法；搜索深度覆盖这些有界入口，但总节点／事件预算仍有限。普通回合仍只有一个主动作，不按入口数增加普通行动。

困难预演必须使用新的调度器：可以出现自己先拿战机、对手先拿战机、普通与战机同刻先后，不得模拟成双方固定交替。

### 13.3 先修旧盲区，再评价新强度

基线审阅指出普通AI会低估逆气／滞气／蚀骨等后续压力，困难预算耗尽可能丢失已选计划后缀。这些是待复现与修复的既有问题，不因换了战机就自动消失。[S5]

增加对公开近期危险的有限检查，不能只在低于半血时才考虑致死威胁。正常与战机的资源保留、技能就绪、对手Z临近满值，应进入可解释的观察。

为对手回应留足独立预算；“三个回应标签”不等于三个实际完整回应。被截断的当前安全状态不能与经历完整反击后的结果直接按同一终点分数比较。记录覆盖到的t、W、R、机会类型和对手已完成动作。

已有计划仍合法时可继续用后缀，失效再按低成本策略降级；不能预算用尽就无条件按第一颗按钮。所有搜索计入同一真实窗口总预算。

### 13.4 性能起点与边界

可保留旧8宽束、256节点、30000模拟事件作为初始实验预算，但应根据新候选空间重测；不得由此宣称必定足够或已达到高手。预留回应预算的具体比例先取至少三分之一，记录不足与降级。

同一观察、同策略参数和同预算下应复现选择。后台线程只解决界面响应，不证明等待短或决策好。分别测单条决策、整个普通窗口、整个战机窗口的时间和截断率。

### 13.5 评价目标

强AI应更好地使用同一套规则，而不是永远压倒每个策略。记录固定顺序、普通、困难在相同输入下的成对结果、失败局面和未决；不能用提高Hmax替代算法改进。

最终要观察：能否以较少资源或较弱人物，通过明确更好的决策改善结果；AI是否随着危险、回转和Z改变安排；是否存在一个固定序列长期通吃。模拟胜率不直接等于人类难度或策略深度。

## 14. 统计、复盘、存档与重试

### 14.1 必须能对账的记录

保留双方总支出、结束H/E、普通回合数R、全部窗口数W、战机次数、主动施法数、基础攻击数、换法数、自动触发数、空窗口与终局原因。

直伤和独立效果伤害分别记录造成方与承受方。气血Cost是支付，不加进伤害。周期组记录伤害请求、恢复请求、实际净气血变化；混合来源不伪造“这一个Buff实际造成了多少”的分摊。

只有伤害或只有恢复的周期组，可以直接报告它的实际损失／恢复；二者并存时以共同净变化和请求量展示。结果页不得把尚未累计的`effect/heal`显示成已证明的零贡献。

战机记录自然新增、各类合格行为新增、上限溢出、不合格来源拒绝原因、安全锁下积累、登记与兑现时点。效果伤害／自动事件不得误入主人主动施法次数。

护体来源奖励开启时，额外校验防护总池与贡献账总量相等；最终伤害与防护不因是否开统计功能而改变。

### 14.2 对账式

```text
本场最终H = 初始H
             - 独立伤害组实际气血损失
             + 独立治疗组实际恢复
             - 已提交气血Cost
             + 各公共周期组实际净变化
             + 其他已明确的H变更
```

任何上限变化、内容修改等额外项都要显式记录，不能塞进“其他”掩盖不守恒。E同理区分支付、自然有效恢复、主动恢复、溢出与其他明确变化。

训练观察上限默认保留600公共刻，并分别设每单位100次普通进入或200次全部窗口上限。任一达到后，在当前原子处理及合法响应完成的安全点记录“观察未结束／未决”；不靠上限判某方获胜，不将它当成游戏内强制狂暴。队列无界或非法状态是执行错误，须另外报错，不与合法但长期未分胜负混同。


### 14.3 快照和规则版本

开战快照固定双方属性、公式／成品版本、P与熟练、配装、法宝模板、初态、Z参数、AI、先后顺序及随机输入。原条件重试恢复这个快照，不能用上一战最终配装、熟练或Z重新生成镜像。

`rules_version`、`content_version`、`save_schema_version`、`ui_version`分开。不能只改界面版本就让旧战斗静默用新阶段继续。

旧进行中战斗不直接按新规则续打。旧W没有区分R，旧J没有新的Z，这些不能从剩余CD推测还原。本版恢复《催》后升级保存结构到4；3.0.0的开战快照不直接重试成新规则，保留旧文件与合法配装并明确重新开战。提供原战前快照按新版本重新开战；保留原档备份。无可靠迁移条件时明示不支持，不丢掉战外配装而不说明。

### 14.4 保存位置边界

首版不强制支持施法中任意保存。允许保存设置、配装、开战快照和安全决策点。若保留进行中安全点存档，需保存A/Z/W/R、票据、安全锁、格子及同源等待、自动标记和阶段。

只有完整实现了队列、结果账本、支付光标及其恢复，才允许组间存档；否则延迟到下一个安全点。读档不重复入场、自动保护、支付、结果引用或战机登记。
